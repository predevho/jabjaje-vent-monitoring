# 잡자재의 기술·상품·용어와 MVP 연결

잡자재가 다루는 상품·서비스·기술 용어를 **한 줄 뜻 → 우리 MVP의 어느 코드·용어와 연결되나 → 면접에서 한마디** 순서로 모았다.
소프트웨어 현업 용어는 [industry-terms.md](industry-terms.md), MVP 도메인 용어는 [GLOSSARY.md](../../GLOSSARY.md), 코드 흐름은 [code-walkthrough.md](code-walkthrough.md)를 본다.

## 출처 표기 규칙

- **[공고]**: 사람인 채용 공고(잡자재 백엔드/IoT 플랫폼 개발자). 사용자가 이미지와 링크로 제공했고, 정리한 내용은 [spec.md 1.1](../spec.md)과 [conversation-log.md #1](conversation-log.md)에 있다.
- **[스펙]**: [docs/spec.md](../spec.md). 공고를 바탕으로 이 프로젝트에서 정한 설계 문서다. 회사가 직접 확인해 준 내용은 아니다.
- **[일반]**: 업계 일반 정의. 회사 고유 정보가 아니다.
- **확인 필요**: 저장소 안에 출처가 없거나, 코드에 "제조사 매뉴얼로 확인해야 한다"고 적어 둔 값. 면접에서 단정하지 말고 질문으로 바꾼다.

## 2. 상품

### KOMFOVENT DOMEKT R (열회수 환기장치)

- **뜻 [일반]**: 열회수 환기장치(HRV/ERV)는 나가는 공기의 열을 들어오는 공기에 옮겨, 환기하면서 냉난방 손실을 줄인다.
- **회사와의 관계 [공고]**: 잡자재가 유통하는 환기장치. 모델 300V/450V/700V.
- **확인 필요**
  - KOMFOVENT라는 제조사 자체에 대한 정보(국적, 회사 규모)는 저장소에 출처가 없다.
  - 모델명의 R과 V가 무엇을 뜻하는지(열교환 방식, 설치 방향 등)
  - 모델별 최대 풍량과 필터 교체 기준 차압. 코드의 값은 **시연용 가정**이다.
  - 장비를 원격으로 읽는 방법(Modbus, BACnet, 제조사 클라우드)
- **MVP 연결**

  | 코드·용어 | 위치 |
  |---|---|
  | 장비 종류 `VENTILATOR`, 용어 "열회수 환기장치" | `site/domain/type/DeviceType.java`, GLOSSARY |
  | 모델명 `DOMEKT R 300V`, `DOMEKT R 450V` (700V는 시드·설정에 없음) | `device.model`, `db/seed/R__demo_seed.sql` |
  | 모델별 최대 풍량 300/450CMH (부스트 상한) | `application.yml`의 `vent.command.boost.model-max-airflow-cmh`. 주석: "실제 최대 풍량은 제조사 매뉴얼로 확인해야 한다" |
  | 모델별 필터 막힘 기준 150Pa | `application.yml`의 `vent.anomaly.filter-clogged`. 주석: "실제 기준값은 제조사 매뉴얼로 확인해야 한다" |
  | 판매 부품 "DOMEKT R 300V/450V 교체 필터 세트" | `application.yml`의 `vent.assessment.parts`. AI 검증기와 판정이 이 목록만 허용 |
  | 측정값 7가지 (CO₂, 온도, 습도, 급기, 배기, 필터 차압, 바이패스) + 부스트 여부 | `telemetry` 테이블, 시뮬레이터 |
  | 바이패스, 필터 차압, 동결 방지 | GLOSSARY, `BYPASS_TOO_LONG`, `FILTER_CLOGGED`, 시뮬레이터의 `FROST_PROTECTION` 거절 |
- **면접에서 한마디**: "MVP는 DOMEKT R 모델을 가정해 모델별 기준(최대 풍량, 필터 차압)을 설정으로 뺐습니다. 실제 값은 제조사 매뉴얼로 채우면 되고, 코드는 바뀌지 않습니다."

### VEMC (자체 컨트롤러)

- **뜻 [공고 → 스펙]**: 주방 후드나 화장실 배기팬이 켜진 것을 감지해 환기장치에 신호를 보낸다. 급기를 올리고 배기를 내려 실내 압력 균형을 맞춘다.
- **확인 필요**
  - VEMC가 환기장치에 신호를 보내는 방식(접점, 0~10V, Modbus 등). [스펙] 역질문 목록에 있다.
  - VEMC가 네트워크에 연결되는지, 이벤트를 밖으로 보낼 수 있는지. MVP는 "VEMC가 HOOD_ON/OFF를 게이트웨이로 보낸다"고 **가정**했다.
- **MVP 연결**

  | 코드·용어 | 위치 |
  |---|---|
  | 장비 종류 `VEMC` | `DeviceType.VEMC` |
  | 후드 연동 = 현장 동작, 서버는 감시만 | ADR-0001, GLOSSARY "후드 연동" |
  | 이벤트 `HOOD_ON`/`HOOD_OFF` 수신 | `hood/` 패키지, `V8__device_event.sql` |
  | 연동 확인 (정상 / 무반응 / 확인 보류) | `HoodInterlockJudge` |
  | 이상 `VEMC_NO_RESPONSE` | `VemcNoResponseAnomalyService` |
  | AI 원인 분류 `VEMC_NOT_LINKED`, 상황 요약의 후드 연동 성공률 | `AssessmentCauseCategory`, `SituationSummary.hoodInterlockSuccessRate` |
- **면접에서 한마디**: "VEMC를 IoT의 씨앗으로 봤습니다. 연동 자체는 인터넷이 끊겨도 돌아야 해서 현장에 두고, 서버는 '후드를 켰는데 급기가 정말 올랐나'를 측정값으로 확인해 VEMC 문제를 고객보다 먼저 찾게 했습니다."

### 복사냉방

- **뜻 [일반]**: 천장·바닥 패널에 찬물을 흘려, 공기를 불어 넣지 않고 표면 복사로 실내를 식히는 방식. 소음과 바람이 적다. 표면 온도가 이슬점보다 낮아지면 결로가 생기므로 습도 관리가 중요하다.
- **회사와의 관계 [공고]**: 잡자재가 유통하는 품목.
- **확인 필요**: 어떤 제품·제조사인지, 원격 제어나 센서가 있는지.
- **MVP 연결**: **없음** (범위 밖).
  - 연결점이 될 수 있는 것: MVP가 모으는 **실내 습도**와 **온도**. 복사냉방은 결로 위험 때문에 습도·이슬점 감시가 핵심이라, 같은 수집 구조(게이트웨이 → MQTT → 측정값)에 장비 종류만 추가하면 된다.
- **면접에서 한마디**: "MVP는 환기만 다뤘지만, 측정값 수집과 이상 규칙 구조가 장비 종류에 묶여 있지 않습니다(`appliesTo(DeviceType)`). 복사냉방이라면 결로 위험 규칙을 하나 추가하는 식으로 확장할 수 있습니다."

### 기밀·단열 자재

- **뜻 [일반]**: 건물 틈으로 공기가 새는 것을 막는 테이프·막(기밀), 열이 빠져나가지 않게 하는 재료(단열). 패시브하우스의 기본이다.
- **회사와의 관계 [공고]**: 잡자재가 유통하는 품목.
- **MVP 연결**: AI 원인 분류 `AIRTIGHTNESS`(기밀 불량). 장비 데이터가 정상인데 불편이 있으면 기밀 점검(블로어도어 테스트)을 권한다(가짜 AI의 마지막 시나리오, 소견 기준표).

## 3. 기술 서비스

### TAB (Testing, Adjusting and Balancing)

- **뜻 [일반]**: 설치 후 실제 풍량을 측정하고 설계대로 맞추는 작업.
- **회사와의 관계 [공고]**: 잡자재의 현장 서비스.
- **MVP 연결**

  | 코드·용어 | 위치 |
  |---|---|
  | 용어 "TAB", "목표 풍량" | GLOSSARY |
  | 목표 풍량의 출처 `TargetAirflowSource.TAB` / `MINIMUM_AIRFLOW` | `site/domain/type/TargetAirflowSource.java` |
  | 목표 풍량은 저장(TAB 값일 수 있어서), 최소 환기량은 계산 | ① 현장 목록 |
  | 이상 `AIRFLOW_BELOW_TARGET` (목표 풍량의 80% 미만 30분) | ④ |
  | AI 원인 분류 `TARGET_AIRFLOW_MISMATCH`, 권하는 점검 "TAB" | `AssessmentCauseCategory`, `recommended_services` |
- **면접에서 한마디**: "목표 풍량을 TAB 값이 있으면 그 값, 없으면 최소 환기량으로 두고, 그 출처를 따로 저장했습니다. CO₂가 높은데 풍량은 목표대로 나오면 목표 자체가 부족하다고 보고 TAB을 권합니다. 회사의 현장 서비스로 이어지는 흐름입니다."

### 블로어도어 테스트

- **뜻 [일반]**: 문에 팬을 달아 실내 압력을 바꾸고, 건물에서 새는 공기량(기밀 성능)을 잰다.
- **회사와의 관계 [공고]**: 잡자재의 현장 서비스.
- **MVP 연결**: AI 원인 분류 `AIRTIGHTNESS`, 권하는 점검 "블로어도어 테스트"(`recommended_services`), GLOSSARY "블로어도어 테스트".

### WUFI 시뮬레이션

- **뜻 [일반]**: 벽체의 열과 습기 이동을 시간에 따라 계산하는 시뮬레이션 프로그램. 결로·곰팡이 위험을 설계 단계에서 본다.
- **회사와의 관계 [공고]**: 잡자재의 기술 서비스.
- **MVP 연결**: **없음** (범위 밖). 실제 측정된 온습도 데이터가 쌓이면 시뮬레이션 결과와 비교하는 데 쓸 수 있다(아이디어 수준).

### 웹 환기량 산정 계산기

- **회사와의 관계 [공고]**: 잡자재가 웹에서 제공하는 계산기.
- **MVP 연결**: **최소 환기량** 계산 `Site.minimumAirflowCmh()` = max(인원 × 30CMH, 바닥면적 × 층고 2.5m × 0.6회/h), 올림. [스펙] 5.3은 이것을 "회사 환기량 산정 기준"이라고 적었다.
- **확인 필요**: 이 계수(30CMH/인, 층고 2.5m, 0.6회/h)가 회사 계산기와 정확히 같은지. 저장소 안에는 계산기 원문 출처가 없다.
- **면접에서 한마디**: "최소 환기량은 저장하지 않고 인원·면적으로 계산합니다. 계수는 설정이 아니라 상수인데, 회사 기준과 다르면 한 곳만 고치면 됩니다."

## 4. 기술·개념

### 패시브하우스

- **뜻 [일반]**: 단열·기밀을 크게 높이고 열회수 환기로 환기 손실을 줄여, 냉난방 에너지를 아주 적게 쓰는 건물.
- **회사와의 관계 [공고]**: 잡자재 상품의 주 고객층.
- **MVP 연결**
  - 프로젝트 이름 자체가 "패시브하우스 환기 모니터링 MVP"다(README, 스펙).
  - 기밀이 높아 **기계 환기가 멈추면 실내 공기가 바로 나빠진다.** 그래서 `CO2_HIGH`, `AIRFLOW_BELOW_TARGET`, `GATEWAY_OFFLINE`이 의미가 있다.
  - 기밀이 높아 주방 후드를 켜면 **음압**이 생기기 쉽다. 그래서 VEMC 후드 연동이 필요하다.
- **면접에서 한마디**: "패시브하우스는 틈이 없어서 환기장치가 곧 숨구멍입니다. 그래서 '장비가 멈췄는지'를 고객보다 먼저 아는 것이 이 MVP의 출발점이었습니다."

### BEMS (Building Energy Management System)

- **뜻 [일반]**: 건물의 에너지 사용과 설비(냉난방, 환기, 조명)를 측정·감시·제어해 에너지를 줄이는 시스템.
- **회사와의 관계 [공고]**: 공고의 주요 업무 "IoT & BEMS 플랫폼 개발".
- **확인 필요**: BEMS 대상이 주택인지, 비주거 건물(사무실, 상가)인지. [스펙] 역질문 목록에 있다.
- **MVP 연결**: MVP는 BEMS의 **감시·제어 뼈대**에 해당한다. 에너지 집계는 아직 없다.

  | BEMS 기능 | MVP에서 | 상태 |
  |---|---|---|
  | 설비 데이터 수집 | 게이트웨이 → MQTT → 측정값 (②) | 있음 |
  | 상태 감시·경보 | 이상 7종 (④·후드·⑤), 게이트웨이 연결 상태 (③) | 있음 |
  | 원격 제어 | 부스트 (⑤) | 있음 |
  | 유지보수 | A/S 신청 → AI 소견 → 판정 (⑥·⑦) | 있음 |
  | 에너지 사용량 집계·절감 분석 | — | **없음** |
  | 건물 설비 프로토콜(BACnet, Modbus) | 게이트웨이가 변환한다고 가정 | **없음** (범위 밖) |
- **면접에서 한마디**: "BEMS를 처음부터 다 만들기보다, 회사가 이미 가진 환기장치와 VEMC부터 수집·감시·제어·A/S를 한 줄로 이었습니다. 에너지 집계는 같은 측정값 위에 올릴 다음 단계입니다."

### IoT 게이트웨이 / MQTT

- **뜻 [일반]**: 게이트웨이는 현장 장비(Modbus 등)를 읽어 인터넷 프로토콜(MQTT)로 바꿔 보내는 장치. MQTT는 가벼운 발행/구독 메시징 프로토콜이다.
- **회사와의 관계**: 공고의 "IoT 플랫폼 개발" [공고]. 잡자재가 지금 게이트웨이를 쓰는지는 **확인 필요**.
- **MVP 연결**: 게이트웨이 시뮬레이터, Mosquitto, 토픽 `jabjaje/{현장}/{장비}/...`, 연결 상태 4개, ACL (②·③·⑧), ADR-0004(판단은 서버에, 메시지는 필드 추가만).

### Modbus / BACnet

- **뜻 [일반]**: Modbus는 산업 장비에서 흔한 단순한 시리얼·TCP 프로토콜이다. BACnet은 건물 설비(BEMS)용 표준 프로토콜이다.
- **회사와의 관계**: **확인 필요**. KOMFOVENT 장비와 VEMC가 어떤 인터페이스를 갖는지 저장소에 출처가 없다.
- **MVP 연결**: **없음** (실제 장비 연동은 범위 밖, [스펙] 1.4). 게이트웨이가 변환한다고 가정했다.
