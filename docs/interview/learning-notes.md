| 바이패스 | 열교환 소자를 거치지 않고 공기를 내보내는 경로 | 오래 지속되면 장비 에러 → `BYPASS_TOO_LONG` |

| TAB | 설계대로 풍량이 나오는지 측정·조정하는 작업 | 설계 환기량의 기준값 |
| 블로어도어 테스트 | 건물 기밀 성능 측정 | AI 진단에서 기밀 불량 의심 시 권유 |
| BEMS | 건물 에너지 관리 시스템 | 공고의 플랫폼 방향 |

## 측정값 7가지 (#43)

| 항목 | 단위 | 판단에 쓰는 곳 |
|---|---|---|
| CO2 농도 | ppm (실내 600~1,000이 보통) | 환기 충분한지 → `CO2_HIGH` |
| 실내 온도 | ℃ | 쾌적성, AI 소견 참고 |
| 실내 습도 | % (40~60% 쾌적) | 결로·곰팡이 위험, AI 소견 참고 |
| 급기 풍량 | CMH | 목표 풍량 비교 → `AIRFLOW_BELOW_TARGET`, 후드 연동 확인 |
| 배기 풍량 | CMH | 급기와 균형(양압·음압) |
| 필터 차압 | Pa (막힐수록 커짐) | 필터 교체 → `FILTER_CLOGGED` |
| 바이패스 여부 | 켜짐/꺼짐 | 오래 켜지면 장비 에러 → `BYPASS_TOO_LONG` |

- 측정값(30초마다 상태) ≠ 이벤트(후드 ON/OFF처럼 일이 생길 때 한 번)
- 핵심 가치: 필터 차압이 오르고 급기가 떨어지는 추세를 보고, 고객이 "답답하다"고 문의하기 전에 알아챈다

## 통신

**MQTT** (#5)
- 브로커를 가운데 둔 발행(publish)/구독(subscribe) 방식
- 토픽 = 채널 이름, `+`와 `#` 와일드카드
- 장비가 먼저 연결하므로 NAT 뒤 장비에도 명령 가능

**QoS** (#5, #7)
- 0: 최대 한 번, 1: 최소 한 번(중복 가능), 2: 정확히 한 번
- QoS 1 + 멱등 처리(messageId)가 실무에서 흔한 조합

**Last Will** (#5, #12)
- 클라이언트가 비정상으로 끊기면 브로커가 미리 맡겨둔 메시지를 대신 발행
- keepalive의 1.5배 시간 뒤 발동

**retained 메시지** (#11)
- 브로커가 토픽의 마지막 메시지를 보관했다가 새 구독자에게 바로 준다
- 상태(online/offline)에는 좋고, 명령에는 쓰면 안 된다(재접속 시 옛 명령 재실행)

**persistent session** (#11)
- 연결이 끊긴 동안의 QoS 1 메시지를 브로커가 보관

**MQTT 5 Message Expiry** (#12)
- 메시지에 유효 시간을 붙여, 지나면 브로커가 전달하지 않고 버린다

**Modbus** (#5)
- 산업 장비 통신 규격. 실제 환기장치는 Modbus → 게이트웨이 → MQTT 구조가 일반적

**OSI 7계층과 프로젝트** (#10)
| 계층 | 프로젝트에서 |
|---|---|
| 7 응용 | MQTT, HTTP |
| 4 전송 | TCP (연결 끊김 감지, half-open 문제) |
| 3 네트워크 | IP, NAT(공유기 뒤 장비에 직접 접속 불가) |
| 1~2 물리·데이터링크 | Wi-Fi/이더넷, 후드-VEMC-환기장치 전선 신호, RS-485 |

**게이트웨이는 계층이 아니라 기기** (#28)
- 현장마다 하나 있는 작은 컴퓨터. 집 안쪽은 Modbus(RS-485 전선), 바깥쪽은 MQTT(TCP/IP, Wi-Fi)로 말한다
- 7계층에서 Modbus → MQTT로 바꿔주는 **응용 계층 게이트웨이**. 내용을 바꾸지 않고 전달만 하는 공유기(3계층), 스위치(2계층)와 다르다
- 데이터에서는 "장비"가 아니라 "연결 통로"로 다룬다. 통로가 끊기면 장비는 "확인 불가"(고장이 아니라 소식을 모르는 상태)

**half-open 연결** (#12)
- 한쪽은 끊겼는데 다른 쪽은 연결된 줄 아는 상태. 그래서 Last Will 외에 무수신 검사도 둔다

## 신뢰성 설계

| 개념 | 한 줄 정의 | 프로젝트에서 |
|---|---|---|
| 멱등성 | 같은 요청을 여러 번 해도 결과가 한 번과 같음 | messageId, commandId (#7, #11) |
| 측정 시각 vs 수신 시각 | 장비가 잰 시각과 서버가 받은 시각을 분리 | 늦은 데이터, 순서 바뀜 대응 (#7) |
| 히스테리시스 | 발생과 해제 기준을 다르게 해 반복 깜빡임 방지 | CO2 1,000 / 900ppm (#8) |
| 지수 백오프 + jitter | 재시도 간격을 늘리고 무작위로 흩뜨림 | 동시 재접속 폭주 방지 (#11) |
| 명령 만료 | 오래된 명령은 실행하지 않음 | `expiresAt` (#11) |
| 자동 복귀 (데드맨) | 해제 명령이 없어도 일정 시간 후 원래대로 | 부스트 `durationSec` (#11) |
| 디바이스 섀도 | 서버는 원하는 상태(desired), 장비는 현재 상태(reported)만 관리 | 명령 몰림의 확장 방향 (#12) |
| 현장 제어 vs 클라우드 | 안전 제어는 현장, 감시·편의는 클라우드 | VEMC 설계 (#8, #9) |
| 하위 호환 | 구버전과 신버전이 함께 동작 | schemaVersion, 필드 추가만 (#15) |
| OTA | 장비 소프트웨어 원격 업데이트. 단계적 배포, 롤백 | 게이트웨이 (#15) |

## 프로젝트 구조 (#33~#36)
- **역도메인 패키지**(`com.회사.제품.기능`): 앞부분(회사)은 외부 배포 라이브러리끼리 이름이 겹치지 않게 하는 장치. 배포하지 않는 실행 앱에는 필요 없다
- **Spring Boot 기본 패키지 금지**: 진입점을 패키지 없이 두면 모든 jar를 컴포넌트 스캔하려 해서 문제가 생긴다 → 최소 한 단계(`vent`)
- **기능별 패키지**: `controller/service/repository` 계층 폴더 대신 `site/`, `telemetry/`처럼 기능 단위로 나누면 깊어지지 않고 용어집과 맞는다
- **모듈 분리**: 진입점(main)이 둘이면 모듈을 나눈다 → `server/`, `simulator/`
- **Gradle 툴체인**: 빌드 도구를 돌리는 Java(25)와 코드를 컴파일하는 Java(17)를 분리할 수 있다

## #1 구현에서 배운 것
- **TDD red → green**: 테스트를 먼저 쓰고 "올바른 이유로" 실패하는지 본다(여기선 API가 없어 404). 그다음 통과할 만큼만 구현한다
- **Testcontainers + @ServiceConnection**: 테스트가 실제 PostgreSQL 컨테이너를 띄우고 접속 정보를 자동으로 연결한다
- **Flyway + `ddl-auto: validate`**: 스키마는 마이그레이션이 만들고, Hibernate는 엔티티가 스키마와 맞는지만 확인한다
- **이미 적용된 마이그레이션을 고치면** Flyway가 체크섬이 다르다며 멈춘다. 배포 전 로컬이면 DB를 지우고 다시, 배포 후라면 새 버전 파일을 추가한다
- **`@EntityGraph`**: 현장 목록과 게이트웨이·장비를 한 쿼리로 가져와 N+1 쿼리를 피한다
- **복합 외래키**: `(gateway_id, site_id) → gateway(id, site_id)`로 "장비의 현장 = 게이트웨이의 현장"을 DB가 보장한다
- **코드 리뷰 두 축**: 표준(규칙·용어·냄새)과 스펙(요구사항)을 따로 봐야 서로 가리지 않는다

## 코딩 규칙 (#40~#41)
- **기능 → 레이어 패키지**: 기능별로 묶고 그 안에서 controller / service / repository / domain / dto로 나눈다. 관련 코드는 한곳에 있고 역할은 폴더로 드러난다
- **트랜잭션은 서비스에서**: 컨트롤러는 요청과 응답만, 트랜잭션 경계와 유스케이스는 서비스가 맡는다
- **엔티티를 응답으로 내보내지 않기**: 응답 DTO(record)로 바꿔서 내보낸다. 엔티티를 바꿔도 API 형태가 흔들리지 않고, 지연 로딩 문제도 피한다
- **@author, @since**: 처음 만든 사람과 날짜만 적고, 수정 이력은 git이 맡는다. 주석 날짜를 계속 고치면 금방 틀어진다

## #2 구현에서 배운 것
- **MQTT 구독 타이밍**: 구독하기 전에 발행된 메시지는 (세션이 없으면) 사라진다. 서버가 "연결 + 구독 완료"를 알려주는 준비 상태가 필요하다
- **PUBACK과 유실**: QoS 1에서 수신 측이 확인 응답을 보내면 브로커는 메시지를 지운다. 저장에 실패했는데 응답을 보내면 유실된다 → 저장 성공 후에만 응답(manual ack)
- **Paho 콜백 규칙**: 콜백 안에서 예외가 나가면 연결이 끊기고, 콜백 스레드에서 동기 호출(구독 등)을 하면 막힐 수 있다
- **ON CONFLICT DO NOTHING**: 중복 messageId를 DB가 걸러 준다. 영향받은 행 수(0/1)로 중복 여부를 안다
- **JPA 이름 규칙 함정**: `co2Ppm`, `tempC`처럼 숫자 뒤나 맨 끝의 대문자 한 글자는 밑줄로 나뉘지 않는다. `ddl-auto: validate`가 앱 시작 때 잡아 준다
- **Flyway 체크섬**: 주석만 바꿔도 체크섬이 달라진다. 커밋된 마이그레이션은 고치지 않고 새 버전을 추가한다
- **시간대**: DB(timestamptz)와 Hibernate를 UTC로 맞추면 서버가 어느 시간대에서 돌든 API 응답 시각이 같다. 화면에서 사용자 시간대로 바꿔 보여 준다
- **java.util.Random**: 시드가 가까우면 처음 값들이 거의 같다
- **React + Spring 한 주소**: Vite 빌드 결과를 Spring Boot 정적 리소스로 넣으면 CORS 없이 주소 하나로 서비스한다. 개발할 때는 Vite 프록시로 `/api`를 넘긴다

## 숫자 밑줄과 MQTT 통신 방식 (#50~#51)
- **숫자 밑줄 `30_000`**: 자릿수 구분자(Java 7+, TS/JS). 값은 30000. 쉼표는 값 구분자라 숫자 안에 못 쓴다. 숫자 사이에만 쓸 수 있다
- **MQTT vs 웹소켓**: 둘 다 연결 하나로 동시에 양방향. 웹소켓은 1:1 직통(전화), MQTT는 브로커 경유 발행/구독(단톡방)
  - MQTT는 받는 대상이 토픽 구독자 전체, 상대가 꺼져 있어도 세션이 있으면 브로커가 보관, QoS·keepalive·Last Will이 기본 기능
  - 패킷: CONNECT/CONNACK, PUBLISH/PUBACK, SUBSCRIBE/SUBACK, PINGREQ/PINGRESP, DISCONNECT
  - 우리 구조: 위로(측정값, #2) + 아래로(명령, #8)를 게이트웨이 연결 하나로. 화면은 HTTP 폴링

## #3 구현에서 배운 것
- **수동 확인 응답(manual ack)**: 처리가 끝난 뒤에만 PUBACK. MQTT는 확인 못 받은 메시지를 재연결 때만 다시 보내므로, 잠깐의 실패는 일부러 재연결한다
- **잠깐의 실패 vs 영구 실패**: 다시 하면 될 수 있는 것(DB 연결 실패)만 재시도, 다시 해도 같은 것(형식 오류, 무결성 위반)은 버린다. 구분을 잘못하면 같은 메시지가 끝없이 돌아온다(**poison message**)
- **Spring 예외 계층**: `TransientDataAccessException`(일시), `DataAccessResourceFailureException`(연결 실패), `DataIntegrityViolationException`(무결성 위반, 영구)
- **지수 백오프 + jitter**: 1초→2초→4초… 기준 최대 60초, ±30% 흔들기. 흔들지 않으면 모든 장비가 같은 순간에 몰린다
- **원형 버퍼**: 크기를 정해 두고 넘치면 가장 오래된 것부터 버린다. 보낸 뒤 PUBACK을 받아야 지운다
- **센서 고장값과 컬럼 크기**: 범위 밖 값도 저장하려면 컬럼이 그 값을 담을 수 있어야 한다. NUMERIC(4,1)은 999.9까지
- **테스트 격리**: 테스트가 로컬에서 실행 중인 브로커에 같은 클라이언트 ID로 붙으면 시연 서버를 끊는다. MQTT가 필요 없는 테스트는 끄고, 필요한 테스트는 ID를 매번 다르게
- **`OffsetDateTime.toString()` 함정**: 0초면 초를 생략한다(06:13Z). 비교할 때는 `ISO_OFFSET_DATE_TIME`으로 포맷한다
- **`@MockitoSpyBean`**: 실제 빈을 감싸서 특정 호출에만 장애를 끼워 넣는다
- **Awaitility `during()`**: "일정 시간 동안 계속 조건이 유지되는지"로 "일어나지 않음"을 확인한다
