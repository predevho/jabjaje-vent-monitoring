# 원격 명령은 "원하는 상태"로 다루고, 만료되며, 장비는 최신 하나만 적용한다

게이트웨이가 일시 끊김 상태일 때 보낸 원격 명령은 브로커에 쌓였다가 다시 연결될 때 한꺼번에 도착할 수 있다. 쌓인 명령을 순서대로 다시 실행하면, 몇 시간 전 부스트가 갑자기 켜지는 것처럼 고객이 원하지 않은 동작이 일어난다. 그래서 원격 명령을 "실행할 동작"이 아니라 "원하는 상태"로 다룬다. 서버는 장비당 대기 중인 명령을 하나만 두고, 모든 명령에 만료 시각을 붙인다(MQTT 5 메시지 만료 + `expiresAt`). 장비는 만료된 명령은 적용하지 않고(`EXPIRED`로 거절), 이미 처리한 `commandId`는 다시 적용하지 않고 이전 결과만 다시 응답하며, 남은 것 중 가장 최신 하나만 적용한다(나머지는 `SUPERSEDED`로 거절). 부스트는 정해진 시간이 지나면 장비가 스스로 원래대로 돌아간다.

## Considered Options

- **명령을 큐에 쌓고 순서대로 실행**: 구현은 단순하지만 오래된 명령이 실행된다. 기각.
- **원하는 상태 + 만료 + 최신 하나만**: 채택.
- **디바이스 섀도(desired/reported 상태 동기화)**: 가장 견고하지만 4일 MVP에는 과하다. 장비가 많아지면 이 방향으로 확장한다.

## Consequences

- 원격 명령의 상태에 `SUPERSEDED`(새 명령에 밀림)와 `late_ack`(시간 초과 뒤 도착한 응답)가 생긴다.
- command 토픽에는 retained 메시지를 쓰지 않는다.
- 나눠서 구현한다. #8은 기본 왕복(보냄 → 적용·거절 응답, retained 없음, 만료 시각을 메시지에 담기만 함, 자동 복귀)이고, #9가 장비당 대기 명령 하나(`SUPERSEDED`), MQTT 5 메시지 만료와 장비의 만료 검사, `commandId` 중복 무시, 재시도·시간 초과, 늦은 응답(`late_ack`)을 더한다.
