# MQTT 브로커는 Eclipse Mosquitto 2를 쓴다

이 프로젝트에 필요한 브로커 기능은 MQTT 5 메시지 만료(ADR-0002), Last Will, retained 메시지, persistent session, 게이트웨이별 계정과 토픽 ACL이다. Mosquitto 2는 이 기능을 모두 지원하고, 이미지가 작으며, 설정이 저장소에 둘 수 있는 짧은 텍스트 파일(설정, 비밀번호, ACL) 몇 개로 끝난다. 1인 개발, 4일, 현장 3곳 규모에서는 이 단순함이 가장 중요하다고 보고 Mosquitto를 고른다.

## Considered Options

- **EMQX**: 클러스터링, 웹 대시보드, 규칙 엔진을 갖춘 대규모용 브로커다. 브로커가 단일 장애점이 되는 문제(스펙 9.1 C12)를 해결할 수 있지만, 무겁고 설정할 것이 많아 MVP에는 과하다.
- **Mosquitto 2**: 채택. 클러스터링이 없다는 한계를 알고 쓴다.

## Consequences

- 운영 규모가 되어 브로커 이중화가 필요하면 EMQX나 매니지드 IoT 서비스로 바꾼다. 게이트웨이와 서버는 표준 MQTT만 쓰므로 바꿀 때 코드보다 설정과 계정 이전이 주된 작업이다.
- #1에서는 익명 접속을 허용하고, 계정과 ACL은 #13에서 켠다.
