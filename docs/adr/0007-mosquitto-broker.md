# MQTT 브로커는 Eclipse Mosquitto 2를 쓴다

이 프로젝트에 필요한 브로커 기능은 MQTT 5 메시지 만료(ADR-0002), Last Will, retained 메시지, persistent session, 게이트웨이별 계정과 토픽 ACL이다. Mosquitto 2는 이 기능을 모두 지원하고, 이미지가 작으며, 설정이 짧은 텍스트 파일(설정, ACL, 비밀번호) 몇 개로 끝난다. 비밀번호 파일은 저장소에 두지 않고 시작할 때 만든다(#13). 1인 개발, 4일, 현장 3곳 규모에서는 이 단순함이 가장 중요하다고 보고 Mosquitto를 고른다.

## Considered Options

- **EMQX**: 클러스터링, 웹 대시보드, 규칙 엔진을 갖춘 대규모용 브로커다. 브로커가 단일 장애점이 되는 문제(스펙 9.1 C12)를 해결할 수 있지만, 무겁고 설정할 것이 많아 MVP에는 과하다.
- **Mosquitto 2**: 채택. 클러스터링이 없다는 한계를 알고 쓴다.

## Consequences

- 운영 규모가 되어 브로커 이중화가 필요하면 EMQX나 매니지드 IoT 서비스로 바꾼다. 게이트웨이와 서버는 표준 MQTT만 쓰므로 바꿀 때 코드보다 설정과 계정 이전이 주된 작업이다.
- #1에서는 익명 접속을 허용했고, #13에서 계정과 ACL을 켰다. ACL은 계정별로 직접 적은 파일(`infra/mosquitto/acl`)이고, 비밀번호 파일은 브로커가 시작할 때 환경변수로 만든다. 현장이 많아지면 dynamic security 플러그인이나 DB 기반 인증으로 바꾼다.
- 계정 이름을 클라이언트 ID로 쓴다(`use_username_as_clientid`). 계정만 있으면 남의 클라이언트 ID로 접속해 그 연결을 끊는 것을 막기 위해서다. 그래서 서버를 여러 대 띄우면 인스턴스마다 계정을 따로 둬야 하고(서버 설정이 client-id와 username이 다르면 시작하지 않는다), 같은 계정으로 두 번 접속하면 먼저 붙은 쪽이 끊긴다. 세션 유지(ADR-0009)와 재연결 재수신(ADR-0012)은 클라이언트 ID 기준이라 계정 이름을 바꾸면 세션도 새로 시작된다.
