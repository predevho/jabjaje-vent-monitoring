# MQTT는 Eclipse Paho MQTT 5 클라이언트를 직접 쓰고, 시뮬레이터는 Java 모듈로 만든다

서버와 가상 게이트웨이(시뮬레이터) 모두 Eclipse Paho MQTT 5 클라이언트를 직접 쓴다. 이 프로젝트는 MQTT 5의 메시지 만료(ADR-0002), 세션 유지(clean start = false), Last Will을 정확히 다뤄야 한다. 라이브러리를 직접 쓰면 연결, 구독, 수신이 코드에 그대로 드러나서 동작을 설명하고 디버깅하기 쉽다. 시뮬레이터는 서버와 같은 언어인 Java로, Spring 없이 가벼운 `main` 프로그램으로 만든다. 이후 티켓에서 시뮬레이터가 버퍼, 재접속, 후드 연동, 원격 명령 응답까지 맡게 되므로 개발자가 직접 읽을 수 있는 언어가 중요하다.

## Considered Options

- **Spring Integration MQTT**: Spring 방식(채널, 어댑터)으로 연결할 수 있지만 내부는 결국 Paho다. 채널과 어댑터 개념이 하나 더 생기고, MQTT 5 옵션을 다루는 코드가 한 단계 감춰진다. 기각.
- **Python 시뮬레이터**: 코드는 짧지만 실행 환경과 언어가 하나 더 생긴다. 기각.

## Consequences

- Paho 콜백 안에서 예외가 밖으로 나가면 연결이 끊긴다. 수신 처리 코드는 모든 예외를 잡고 로그를 남겨야 한다.
- 서버는 브로커가 아직 없어도 뜰 수 있어야 하므로, 첫 연결을 백그라운드에서 재시도한다.
