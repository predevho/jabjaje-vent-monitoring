# 진입점마다 모듈을 나누고, 패키지는 `vent` 한 단계에서 기능별로 넓힌다

서버 앱과 가상 게이트웨이(시뮬레이터)는 진입점이 다르므로 저장소 루트에서 `server/`, `simulator/`로 나눈다. 폴더 이름만 보고 무엇을 실행하는지 알 수 있게 하기 위해서다. 패키지는 관례적인 역도메인 이름(`io.github.predevho.vent`) 대신 `vent` 한 단계로 둔다. 역도메인 이름은 외부에 배포하는 라이브러리의 이름 충돌을 막는 장치인데, 이 프로젝트는 배포하지 않는 실행 앱이라 그 단계가 하는 일 없이 깊이만 늘린다. Spring Boot는 진입점을 기본 패키지에 둘 수 없으므로 한 단계는 유지한다. `vent` 아래는 `controller/service/repository` 같은 계층 폴더가 아니라 `site/`, `telemetry/`, `anomaly/`처럼 용어집의 기능 단위로 옆으로 넓힌다.

## Considered Options

- **역도메인 패키지 유지**: 관례를 지키지만 진입점까지 9단계가 된다. 기각.
- **회사 이름 패키지(`jabjaje.vent`)**: 회사 코드처럼 보일 수 있다. 기각.
- **`src/main/java` 경로 변경**: Gradle, IDE, Docker 빌드의 기본 경로라 바꾸면 설정이 여러 곳에서 늘어난다. 유지.

## Consequences

- 이 코드를 라이브러리로 외부에 배포하게 되면 역도메인 패키지로 바꿔야 한다.
- 서버와 시뮬레이터가 같이 쓰는 메시지 형식이 생기면 `vent` 아래 공유 패키지나 별도 공유 모듈로 둔다.
