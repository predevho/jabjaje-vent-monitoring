# 판단 로직은 서버에 두고, 게이트웨이 메시지는 필드 추가만 허용한다

게이트웨이 소프트웨어 업데이트는 실패하면 기사가 현장에 가야 해서 비싸고 위험하다. 그래서 이상 기준, 규칙, AI 소견, 화면처럼 판단이 들어가는 로직은 모두 서버에 두고, 게이트웨이는 측정, 전달, 원격 명령 적용, 후드 연동만 한다. 기능 변경 대부분이 서버 배포로 끝난다. 현장에는 버전이 다른 게이트웨이가 섞여 있으므로, 메시지에 `schemaVersion`을 넣고 형식 변경은 필드 추가만 허용한다. 게이트웨이는 연결될 때 자기 버전과 지원 기능을 보고하고, 서버는 지원하지 않는 원격 명령을 보내지 않는다.

## Consequences

- 서버는 모르는 필드를 무시해야 한다.
- 필드 삭제나 의미 변경이 필요하면 `schemaVersion`을 올리고, 구버전 게이트웨이가 남아 있는 동안 두 버전을 함께 처리한다.
- 측정 항목 추가(예: 미세먼지 센서)처럼 하드웨어가 바뀌는 변경은 이 원칙으로도 피할 수 없다.
