# AI 소견은 공식 Java SDK로 Claude를 부르고, 구조화 출력과 고정 평가 세트로 품질을 잰다

A/S 신청의 AI 소견(ADR-0005)을 실제 Claude로 받는다(#12). 정한 것은 네 가지다.

1. **호출 방식**: Anthropic 공식 Java SDK(`com.anthropic:anthropic-java`)를 쓴다. 요청·응답 타입, 시간 제한, 재시도, 오류 종류(요청 한도 초과, 과부하, 인증 실패)를 SDK가 주므로, "다시 시도할 실패"와 "사람에게 넘길 실패"를 깔끔하게 나눌 수 있다. API에 막 나온 베타 기능(거절 시 서버 재실행 `fallbacks: "default"`)은 SDK의 추가 필드·헤더로 보낸다.
2. **모델**: 기본은 `claude-opus-5-5`, 생각의 양(effort) `medium`. Opus 5.5는 생각을 끌 수 없어 effort로만 조절한다. 1차 시도 모델과 검증 실패 뒤 재시도 모델을 따로 설정할 수 있게 해서, 싼 모델을 먼저 쓰고 실패하면 강한 모델로 올리는 단계적 승격을 설정만으로 켤 수 있다. 기본은 둘 다 Opus(승격 꺼짐).
3. **출력 형식**: 구조화 출력(`output_config.format`, 고정 JSON 스키마)으로 형식을 API가 강제한다. 가능성·원인 분류·근거 지표·부품·권하는 점검은 정해진 값만 허용한다. "값이 있는 지표만 근거로", "고객 안내문에 금액·무상 약속 없음"은 스키마로 표현할 수 없어 기존 검증기가 두 번째 안전장치로 남는다.
4. **품질 측정**: 원인마다 분류(`category`, 8가지, 소견 기준표와 1:1)를 내게 하고, 고정된 상황 요약 5개로 1순위 분류가 정답인지 센다. 채점이 "값이 같은가"라서 채점용 AI가 필요 없고 결과가 흔들리지 않는다.

## Considered Options

- **HTTP 직접 호출(Spring RestClient)**: 의존성이 없고 요청이 투명하다. 하지만 요청·응답 JSON, 오류 코드별 처리, 재시도를 모두 직접 짜야 하고, API가 바뀌면(예: `thinking` 설정 방식, 없어진 파라미터의 400) 직접 따라가야 한다. 이 기능은 실패 처리가 핵심이라 기각.
- **프롬프트로만 JSON 요청**: 가장 단순하지만 형식이 깨지면 재시도가 늘어 시간과 비용이 든다. 기각.
- **도구 호출로 소견 받기**: Opus 5.5는 특정 도구 호출을 강제할 수 없어 글로 답할 수 있다. 구조화 출력이 이 용도의 표준이다. 기각.
- **규칙 기반·분류 모델 라우팅**: 입력을 보고 모델을 고르는 방식. A/S 신청은 하루 수십 건이라 아끼는 돈이 작고, 분류 모델 라우터는 호출이 매번 하나 는다. 측정 근거 없이 규칙을 정하게 되어 기각. 단계적 승격만 설정으로 지원한다.
- **채점용 AI 또는 키워드 매칭으로 채점**: 채점용 AI는 비용과 흔들림이 생기고, 키워드 매칭은 "필터는 정상" 같은 부정문에 틀린다. 기각.
- **시뮬레이터로 평가 시나리오 만들기(스펙 원안)**: 상황 요약이 7일치 측정값을 요구해 실제로 7일을 돌려야 하고, 돌릴 때마다 값이 달라 모델·프롬프트 비교가 공정하지 않다. Docker 시연에서 본 값을 참고해 상황 요약 자체를 고정한다.

## Consequences

- 실행 파일에 SDK와 OkHttp가 들어간다. Jackson은 Spring과 같은 버전으로 맞춰진다.
- 시도 한 번의 최대 시간은 `timeout × (max-retries + 1) + 재시도 대기(60초 × max-retries)` = 60초 × 2 + 60초 = 3분이다. 재처리 기준(7분)은 3분 × 시도 2번보다 길어야 해서 앱이 시작할 때 검사한다(ADR-0015).
- 다시 해도 같은 실패(안전 거절, 잘못된 요청, 인증·권한 실패)는 재시도하지 않는다. 같은 입력으로 다시 불러도 비용만 든다. 안전 거절은 서버가 이미 다른 모델로 다시 실행해 본 결과다.
- 서버 재실행(`fallbacks`)은 이 기능이 있는 모델(Opus 5.5·Opus 5·Sonnet 5.5·Fable 5.1)에만 보낸다. Haiku 5.5를 1차 모델로 쓰면 거절이 그대로 `REFUSAL`이 된다.
- 거절(`refusal`), 응답 잘림(`max_tokens`)은 성공 응답(200)으로 와도 실패로 본다. 서버 재실행으로 다른 모델이 답하면, 실제로 답한 모델 이름이 기록에 남는다.
- 시스템 프롬프트는 버전 파일(`prompts/assessment-system-v1.md`)로 두고, 버전을 AI 입력 사본과 평가 보고서에 남긴다. 프롬프트를 고치면 새 버전 파일을 만들고 평가를 다시 돌린다.
- 프롬프트 캐싱은 켜지만 운영 효과는 작다. 캐시가 5분만 유지되는데 A/S 신청은 그보다 드물게 온다. 효과는 평가 세트 실행과 같은 모델 재시도에서 난다.
- 테스트는 키가 있어도 가짜 AI만 쓴다(`src/test/resources/config/application.properties`). 실제 Claude는 평가 명령에서만 부르고, 그때만 비용이 나간다.
- 평가 실행기는 운영과 같은 `application.yml` 설정과 같은 호출부 생성 방법을 쓰고, 프롬프트의 JSON(시각 형식 포함)도 운영과 글자 하나까지 같다. 시도 순서만 실행기에 따로 있다(운영 쪽은 DB 저장이 섞여 있다).
